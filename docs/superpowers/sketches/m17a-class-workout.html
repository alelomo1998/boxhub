M17a · the class workout screen — three ways the same class reads at 360px

Reached by a row on class detail, shown only when the coach has published the programming (the server already returns nothing otherwise). It is a read-only visual of the class — no score logging, no leaderboard links; those stay on M17b's WOD board.
It is a detail screen: no dock, back arrow at top left returning to the class, and therefore — by your 2026-09-18 ruling — no volt anywhere on it. So identity here has to come from the mono prescription voice, type scale and spacing, never from colour. All three options obey that; they differ in how loud the prescription is.
Header title is "Workout", not the class name, with the class named in the mono line just below — otherwise this screen's header is identical to the class's and you can't tell you moved. Reject that if you'd rather the header repeat the class name.
Same data in all three: the seeded demo class — Row + mobility, Back Squat 5x5 @ 80%, Fran, AMRAP 10.
Heights are measured, not estimated (Playwright, 702px of scrollable viewport at 360px wide): C 621px (4 of 4 fit) < A 740px (3 of 4) < B 834px (3 of 4). My first captions guessed A at "2.5 pieces" and called C the expensive one; both were wrong, which is why the rule says measure.

A · piece cards

Each piece is a --surface card, the same idiom as class detail's own surfaces and the rest of the app. Safest and most familiar; the card edges do the separating work. Cost (measured): the four pieces run 740px in a 702px viewport — 3 of 4 fit, so the class always needs a scroll. Reads as plumbing rather than as a gym's workout.

B · board sheet

No cards at all — pieces sit flat on --ground, separated by hairline rules, with the prescription set large in mono (--fs-h2 reps + movement). Reads like the gym's whiteboard, which is what an athlete actually checks before class. Most identity of the three, and it earns it through type rather than colour. Cost (measured): the tallest by a clear margin — 834px for four pieces in a 702px viewport, 3 of 4 fit. A 10-line chipper gets very tall, and with no card edge two short adjacent pieces run together.

C · run of class

A rail down the left orders the hour — warmup → strength → workout — so the screen answers "how does this class run", not just "what's in it". Closest to the question an athlete deciding whether to book is actually asking. Measured — and this surprised me: it is the most COMPACT of the three, not the most expensive. 621px for four pieces, the only option where all 4 fit in the 702px viewport with no scroll, because dropping the card padding buys back more than the rail costs. Real cost: the rail takes 20px of horizontal room on every line, and it implies a timeline the data does not have — pieces carry no durations, so it orders them and nothing more.
