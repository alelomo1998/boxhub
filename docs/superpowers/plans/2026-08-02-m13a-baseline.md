# M13a Baseline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move three baselines — Angular version, the URL the app lives at, and the absence of i18n — without changing how anything looks.

**Architecture:** Ten live tasks in a forced order (Task 3 was cut — see its entry). The Angular majors go one at a time, each fully gated, with Karma and `zone.js` retained throughout. The `/app` move splits `boxhub.app-url` into an origin and an app-base, because its three consumers do not all want the same value. i18n lands last, because it touches every string and would conflict with everything before it.

**Tech Stack:** Angular 19.2 → 22, Karma, Spring Boot 3.5 / Java 21, Flyway, nginx, Playwright.

## The defining constraint

**Nothing in this milestone changes how anything looks.** Every screen renders identically before and
after. That is what makes a milestone containing three Angular majors, a runner migration, a URL move
and i18n verifiable at all. A visual difference means something broke.

## Hardening invariants — binding, escalate rather than relax

1. **`backend/src/test/java/com/boxhub/security/AuthzConformanceTest.java` is not edited.** The API
   stays at `/api`, so the `/app` move should not touch the route table at all. If that test fails,
   it is a finding to report, not a file to change.
2. **`SecretDefaultsTest` and `LogHygieneTest` keep passing unchanged**, including M12c's PII
   assertions. i18n touches `Mailer`; its masking and the address assertions stay exactly as strict.
3. **The CSP, the five security headers and `secure_link` media validation survive the nginx work.**
   `add_header` *replaces* rather than merges — a new location that declares one loses every inherited
   server-level header.
4. **`OAuth2SecurityConfig`'s `redirect_uri` must NOT gain the `/app` prefix.** This is the sharpest
   edge in the milestone; see Task 5.
5. **No visual change.** See above.

### Task 3: Karma → Vitest — **CUT 2026-08-02, before any code was written**

**Do not implement this. It is left in place rather than deleted so the reasoning is traceable.**

The task existed on two claims, both from a secondary web article, and **both turned out to be false**:

1. *"Angular 22 removes Karma."* It does not. Verified against the published package:
   `@angular-devkit/build-angular@22.1.2` ships a `karma` builder with an implementation, a schema,
   the description "Run Karma unit tests", and a `karma ^6.3.0` peer dependency.
2. *"Migrate with `ng generate @angular/core:karma-to-vitest`."* That schematic does not exist. The
   executor dispatched to run it got `Schematic "karma-to-vitest" not found in collection
   "@angular/core"` and **stopped instead of hand-rolling a migration** — which is what made the
   first claim worth re-checking rather than trusting.

The independent speed argument had already died: Karma runs the 184 specs in **~4 seconds**. The
documented "~1 hour" was iCloud materialising dataless files, not the runner.

With no compatibility requirement and no performance case, what remained was translating **43 spec
files — 30 of them using `HttpTestingController`** — off Jasmine, with no compatibility shim in
`@angular/build`'s vitest runner, driven by an experimental hidden schematic. Cut.

**Filed in `docs/BACKLOG.md`** against whichever Angular release actually removes Karma, to be done
then with a real migration path.

**The transferable lesson:** one wrong fact from a source is reason to re-check its other facts. Both
claims here came from the same article; catching the cheap one is what exposed the expensive one.

```java
package com.boxhub.shared;

import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;

/**
 * The single place that knows where BoxHub's URLs point.
 *
 * Two methods, deliberately named so the choice is obvious at every call site:
 *
 *  - {@link #appLink} — the Angular application, which lives under {@code boxhub.app-base}
 *    (default {@code /app}). Emailed links and the Stripe return URLs use this.
 *  - {@link #origin} — the bare server root. The OAuth2 callback lives here, NOT under /app,
 *    because nginx proxies /login/oauth2/ at the root and Google matches redirect_uri against a
 *    console registration. Prefixing it breaks Google SSO in production and nowhere else, which
 *    is the bug M12c fixed on 2026-07-29.
 */
@Component
public class AppUrls {

    private final String origin;
    private final String base;

    public AppUrls(@Value("${boxhub.app-url}") String appUrl,
                   @Value("${boxhub.app-base}") String appBase) {
        this.origin = appUrl.endsWith("/") ? appUrl.substring(0, appUrl.length() - 1) : appUrl;
        this.base = appBase.endsWith("/") ? appBase.substring(0, appBase.length() - 1) : appBase;
    }

    /** Absolute URL into the Angular app, e.g. appLink("/auth/verify?token=abc"). */
    public String appLink(String path) {
        return origin + base + path;
    }

    /** The bare server origin, with no app base. For the OAuth2 redirect-uri only. */
    public String origin() {
        return origin;
    }
}
```

Add to `backend/src/main/resources/application.yml`, next to `app-url`:

```yaml
  # server root. See AppUrls — prefixing the OAuth redirect-uri breaks Google SSO in production only.
  app-base: ${BOXHUB_APP_BASE:/app}
```

### Task 6: `/app` — frontend, nginx, redirects, e2e

**Files:**

- Modify: every spec in `e2e/tests/`

**Interfaces:**
- Consumes: `AppUrls.appLink` from Task 5.
- Produces: the app served at `/app`, `/` redirecting there, old paths permanently redirected.

**Context.** `frontend/src/index.html:6` is `<base href="/">`. nginx's SPA `location /` does
`try_files $uri $uri/ /index.html` with `sub_filter` injecting the CSP nonce, and there is a separate
`location = /index.html` no-cache block. The API stays at `/api`, the OAuth chain at
`/oauth2/` and `/login/oauth2/`, media at `/media/` — **none of those move.**

**`bh_rt` is `Path=/api/auth` and the API does not move, so no cookie path changes.** Stated because
MockMvc does not enforce RFC 6265 path matching, so a mistake here passes every backend test and
fails only in a real browser — which shipped once already (M8-T9).

**Already-sent emails must keep working.** Verification, reset, invite and email-change links in real
inboxes point at `/auth/verify?token=`, `/join/<token>` and friends. Those tokens are single-use and
time-limited; a dead link is unrecoverable for that user. nginx keeps **permanent** redirects from
the old app paths, preserving query string and path parameters.

**e2e cannot simply change `baseURL`.** The specs mix app routes (`/athlete/home`, `/admin/members`,
`/auth/login`) with API routes (`/api/me`, `/api/auth/csrf`, `/api/auth/logout`), and the API stays at
the root. App routes get the `/app` prefix in the specs; API routes do not.

```ts
// carry single-use, time-limited tokens, so a dead link is unrecoverable for that user. nginx keeps
// permanent redirects, query string and path parameters intact.
test('old app paths permanently redirect into /app, preserving tokens', async ({ request }) => {
  const q = await request.get('/auth/verify?token=abc123', { maxRedirects: 0 });
  expect(q.status()).toBe(301);
  expect(q.headers()['location']).toBe('/app/auth/verify?token=abc123');
```
